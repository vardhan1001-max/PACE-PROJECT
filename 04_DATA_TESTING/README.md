# 04_DATA_TESTING — Datasets, Validation, Testing, Reports & Documentation

Owner: **Data + Testing** team member. This folder owns raw/processed data
organization, data-quality/validation, the test suite, generated reports,
and all project documentation. It contains no Flask routes, no ML training
code, and no HTML/CSS/JS (beyond what's embedded in generated report/EDA
figure files).

## Structure

```
04_DATA_TESTING/
├── datasets/
│   ├── raw/         — original, unmodified source data (kept separate from processed)
│   └── processed/   — pipeline-generated CSVs (gitignored — regenerate, don't hand-edit)
├── validation/       — data-quality/schema validation (see note below)
├── testing/
│   └── smoke_test_flask_app.py  — real, runnable smoke test (see below)
├── reports/
│   ├── figures/      — 18 EDA/model PNGs (gitignored — regenerate via the pipeline)
│   └── *.json        — metrics + insights (gitignored — regenerate via the pipeline)
└── documentation/     — every project doc (moved here from the old docs/ folder)
```

## Dataset sources

- **E-Commerce Customer Churn** (Kaggle, "Ecommerce Customer Churn Analysis
  and Prediction" by Ankit Verma) — the primary, per-customer snapshot
  dataset with a real `Churn` label. Ships in this repo as
  `datasets/raw/ecommerce_churn.csv.zip` (the original `.xlsx` export,
  zipped). **Convert the `.xlsx` inside to CSV and save it as
  `datasets/raw/ecommerce_churn.csv`** before running the pipeline — see
  `documentation/INSTALLATION.md`.
- **Online Retail II** (UCI/Kaggle, optional) — a real transaction log used
  only to make revenue trends, geography and market-basket recommendations
  genuinely real instead of proxies. Not bundled (large file); place it at
  `datasets/raw/online_retail_II.xlsx` if you want this layer. Every
  downstream page works without it — it just shows an honest "unavailable"
  state for the features that need it.

## Dataset structure

- `datasets/raw/` — exactly what was downloaded, never edited by hand.
- `datasets/processed/` — everything the pipeline (`02_ML_AI/run_pipeline.py`)
  writes: `raw_enriched.csv` → `cleaned_data.csv` / `cleaned_readable.csv` →
  `segmented_data.csv` → `final_customer_data.csv` → `customer_recommendations.csv`.
  These are gitignored on purpose (regenerate, don't commit large derived
  CSVs) — the folder ships with only a `.gitkeep` placeholder.

## Validation process

This project did not have a formal data-validation module before this
restructure. What already exists and still runs:
`02_ML_AI/data_loading/01_data_loading.py` validates the raw file has all 20
expected columns and fails loudly (not silently) if the schema doesn't
match a different Kaggle dataset. This `validation/` folder is the intended
home for anything beyond that — e.g. row-count sanity checks, null-rate
thresholds, or a `pandera`/`great_expectations` schema — and is left empty
rather than filled with placeholder validation that doesn't actually check
anything. See "Remaining issues" in the restructure report for this
project's current state.

## Test cases

`testing/smoke_test_flask_app.py` is new (added during this restructure,
not moved from anywhere — the project had no automated tests before). It
boots the real Flask app in-process (Flask's test client, no server, no
network) and asserts every route returns HTTP 200, plus a login/logout
round-trip. Run it with:

```bash
cd PACE-Customer-Intelligence-System
python 04_DATA_TESTING/testing/smoke_test_flask_app.py
```

It was run against this restructured layout — after a full pipeline run —
and passed (17/17 routes + login/logout). It's intentionally minimal: a
foundation to extend with real assertions (e.g. "the churn probability
column is always between 0 and 1", "segmentation always yields ≥2
segments") rather than a full test suite.

## Bug reporting

No formal bug tracker is wired up for this project. Until the team sets one

during testing directly in this README or in a new
`documentation/KNOWN_ISSUES.md` you create, with: what you ran, what you
expected, what happened, and the exact error/traceback.

## Reports

`reports/*.json` + `reports/figures/*.png` are 100% generated by the
`02_ML_AI` pipeline — nothing in this folder is hand-authored. They're
gitignored so the repo doesn't carry regenerable binary/derived files;
running `python 02_ML_AI/run_pipeline.py` recreates all of them.
